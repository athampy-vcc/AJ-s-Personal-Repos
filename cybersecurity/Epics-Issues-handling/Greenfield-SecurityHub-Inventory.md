# Greenfield Accounts Security Hub Inventory and CIS Benchmark Recommendation
## 1) Why not only CIS v1.4.0, v3.0.0, or v5.0.0?
- **Security Hub now supports CIS AWS Foundations Benchmark versions 1.2.0, 1.4.0, 3.0.0, and 5.0.0.** The latest generally available version supported by Security Hub is **v5.0.0**, while **v3.0.0** is also fully supported.
- **Using v3.0.0 or v5.0.0 is absolutely reasonable for new / greenfield accounts.** For a greenfield program, the default should usually be the newest benchmark that Security Hub supports **unless** you need backward comparability to older evidence or existing exception handling mapped to older control IDs.
- **Important caveat:** the uploaded findings show many service-specific controls from AWS Foundational Security Best Practices (FSBP) beyond the scope of the CIS AWS Foundations benchmark (for example API Gateway, Macie, GuardDuty, Inspector, ECR, ECS, Secrets Manager, DynamoDB, EFS, CloudFormation, SSM, ELB, Kinesis). Therefore, **CIS alone is not enough** as the sole posture standard for these accounts; you should use **CIS AWS Foundations + AWS FSBP** together.

## 2) Recommendation
- **Recommended target benchmark for greenfield accounts:** **CIS AWS Foundations Benchmark v5.0.0** as the forward-looking baseline.
- **Use v3.0.0 only if** you need a lower-change transition step from older versions or if your internal compliance documentation / evidence packs are already built around the v3.0.0 control set.
- **Keep AWS Foundational Security Best Practices enabled in parallel** to cover the service-specific findings that CIS AWS Foundations does not fully cover.
- **Migration practical answer:** keep existing legacy accounts on their current benchmark during transition, but enable **v5.0.0** for greenfield accounts and carry over suppressions / control state using Security Hub central configuration.

## 5) Interpretation for CIS version selection
- The matched findings already include **legacy CIS findings (v1.2.0 and v1.4.0)** plus many **AWS FSBP** findings. This indicates your current environment is being assessed with older CIS versions plus a broader AWS service posture standard.
- Because the greenfield accounts show a mix of **foundational issues** (IAM, logging, monitoring, networking, storage) **and non-foundational service findings**, the best operating model is:
  1. **Adopt CIS AWS Foundations v5.0.0** for baseline account governance, logging, IAM, storage, and network hygiene.
  2. **Keep AWS FSBP enabled** for service-specific hardening.
  3. Use **v3.0.0 only** if you need a temporary intermediate benchmark to simplify control mapping from v1.4.0.
- In short: **Yes, v3.0.0 and v5.0.0 are good to use. For greenfield, v5.0.0 is the better target.**

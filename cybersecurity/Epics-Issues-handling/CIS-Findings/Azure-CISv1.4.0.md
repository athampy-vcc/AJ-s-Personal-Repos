# Azure CIS 1.4.0 – Prisma CNAPP Remediation Matrix (Greenfield Environment)

## Purpose
This document consolidates the Azure CIS 1.4.0 findings and provides a high-level remediation matrix for each benchmark. It also recommends the control layer where remediation should be applied and gives a qualitative view of the likely security score uplift once the control is implemented.

## Important note
- The benchmark counts in this document come from the provided Prisma CNAPP exports.
- The remediation approach, remediation level, and expected security score influence are recommended guidance to support planning. They are **not** direct fields from the source export and should be validated against your design standards, exception model, and rollout constraints.
- "Expected Security Score Influence" is **qualitative**. It is **not** an exact Microsoft Secure Score or Defender for Cloud score-point estimate.

## Recommended Rollout Pattern for a Greenfield Azure Environment
1. **Tenant and platform baseline first** – implement identity, Microsoft Defender for Cloud, Activity Log alerts, and diagnostic settings before onboarding application workloads.
2. **Enforce with policy where possible** – prefer management group or subscription level policy assignments for preventive or deploy-if-not-exists controls, then handle service-specific gaps at the resource level.
3. **Prioritize broad-exposure controls** – public exposure, weak identity posture, missing monitoring, and absent security plans generally create the most visible early uplift.
4. **Standardize exceptions** – if a benchmark cannot be remediated immediately, register an exception with owner, rationale, expiry, and compensating control.
5. **Measure after each wave** – track failed-resource count trend per benchmark after each remediation sprint to validate that compliance and score trajectory are improving.
